ساخت و انتشار برنامه (Publish)

انتشار فایل‌های وب (ForgeFlow.Web)

در سرور بیلد یا سیستم استقرار، پروژه وب را با پیکربندی Release منتشر کنید. فایل packages.lock.json باید دست‌نخورده بماند.

PowerShell — پوشه ریشه مخزن
dotnet publish .\src\ForgeFlow.Web\ForgeFlow.Web.csproj -c Release -o .\publish\web

انتشار ابزار مقداردهی اولیه (ForgeFlow.Bootstrap)

این ابزار فقط روی میزبان استقرار (نه در پوشه عمومی IIS) قرار می‌گیرد و برای ساخت اولین ادمین یا بازیابی رمز استفاده می‌شود.

PowerShell — پوشه ریشه مخزن
dotnet publish .\tools\ForgeFlow.Bootstrap\ForgeFlow.Bootstrap.csproj -c Release -o .\publish\bootstrap

انتقال به مسیرهای جداگانه روی سرور

پوشه .\publish\web را به C:\inetpub\forgeflow\ و پوشه .\publish\bootstrap را به یک مسیر مدیریتی محدود مثل C:\ops\forgeflow-bootstrap\ کپی کنید.

پیکربندی، Data Protection و امنیت

تنظیم رشته اتصال و محیط اجرا

برنامه کلید ConnectionStrings:ForgeFlow (یا متغیر محیطی ConnectionStrings__ForgeFlow) را می‌خواند. در محیط Production، این مقدار را از طریق appsettings.Production.json (در پوشه C:\inetpub\forgeflow\ با دسترسی NTFS محدود) یا متغیر محیطی IIS تنظیم کنید:

appsettings.Production.json
{ "ConnectionStrings": { "ForgeFlow": "Server=SQLHOST;Database=ForgeFlow;User Id=forgeflow_runtime;Password=STRONG_PASSWORD;Encrypt=True;TrustServerCertificate=False;" }, "Logging": { "LogLevel": { "Default": "Warning" } }, "AllowedHosts": "forgeflow.company.local" }
⚠️
برنامه هنگام استارتاپ هرگز Migration یا Seed خودکار انجام نمی‌دهد. بنابراین حساب forgeflow_runtime نباید db_owner باشد؛ نقش ForgeFlowOrganizationRuntime و دسترسی‌های حداقلی برای آن کافی است.

ایجاد پایگاه داده و اجرای Migration‌ها

مرحله ۵.۱ — ایجاد پایگاه‌داده و تفکیک حساب Provisioning و Runtime

در معماری ForgeFlow، حسابی که Migration‌ها و Bootstrap را اجرا می‌کند (دارای db_owner) باید از حساب اجرای عادی وب (forgeflow_runtime) جدا باشد:

SQL Server (با دسترسی sysadmin / dbcreator)
CREATE DATABASE ForgeFlow; GO -- حساب موقت/عملیاتی برای اعمال Migration و اجرای Bootstrap CREATE LOGIN forgeflow_provision WITH PASSWORD = 'PROVISION_STRONG_PASS'; -- حساب محدود برای اجرای عادی وب‌اپلیکیشن CREATE LOGIN forgeflow_runtime WITH PASSWORD = 'RUNTIME_STRONG_PASS'; USE ForgeFlow; CREATE USER forgeflow_provision FOR LOGIN forgeflow_provision; ALTER ROLE db_owner ADD MEMBER forgeflow_provision; CREATE USER forgeflow_runtime FOR LOGIN forgeflow_runtime; -- پس از اعمال مایگریشن‌ها، عضویت زیر توسط اسکریپت‌های مایگریشن یا DBA تکمیل می‌شود

مرحله ۵.۲ — اعمال Migration برای هر ۳ DbContext

ساختار دیتابیس از ۳ کانتکست مستقل تشکیل شده است که باید با رشته اتصال Provisioning به ترتیب زیر اعمال شوند:

PowerShell — از پوشه ریشه مخزن (با نصب بودن dotnet-ef)
$env:ConnectionStrings__ForgeFlow = "Server=SQLHOST;Database=ForgeFlow;User Id=forgeflow_provision;Password=PROVISION_STRONG_PASS;Encrypt=True;" # ۱) کانتکست احراز هویت (۶ مایگریشن) dotnet ef database update --context AuthDbContext --project .\src\ForgeFlow.Infrastructure --startup-project .\src\ForgeFlow.Web # ۲) کانتکست سازمان، تولید، انبار، خرید و آزمایشگاه (۱۲ مایگریشن) dotnet ef database update --context OrganizationDbContext --project .\src\ForgeFlow.Infrastructure --startup-project .\src\ForgeFlow.Web # ۳) کانتکست خطاها و لاگ عملیاتی (۱ مایگریشن) dotnet ef database update --context DiagnosticsDbContext --project .\src\ForgeFlow.Infrastructure --startup-project .\src\ForgeFlow.Web
ℹ️
می‌توانید به جای اجرای مستقیم dotnet ef database update روی سرور نهایی، اسکریپت‌های Idempotent را با dotnet ef migrations script --idempotent تولید کرده و توسط DBA در SQL Server اجرا کنید.

راه‌اندازی اولیه با ForgeFlow.Bootstrap

مرحله ۶.۱ — ایجاد اولین ادمین، سازمان و سایت

ابزار ForgeFlow.Bootstrap هیچ رمز عبوری را در آرگومان خط فرمان قبول نمی‌کند و فقط در یک ترمینال تعاملی (Interactive) اجرا می‌شود.

تنظیم متغیر اتصال Provisioning در نشست جاری

$env:FORGEFLOW_BOOTSTRAP_SQLSERVER = "Server=SQLHOST;Database=ForgeFlow;User Id=forgeflow_provision;Password=PROVISION_STRONG_PASS;Encrypt=True;" .\ForgeFlow.Bootstrap.exe initialize-deployment

ورود تعاملی مقادیر در ترمینال

برنامه سرور و دیتابیس هدف را نمایش می‌دهد و به ترتیب این موارد را می‌پرسد:

  • تایپ عبارت دقیق INITIALIZE برای تأیید مسئولیت اپراتور
  • Operation ID (با Enter یک GUID جدید ساخته می‌شود؛ آن را یادداشت کنید)
  • نام کاربری ادمین اولیه (Initial account username)
  • کد سازمان (Organization code) و نام سازمان (Organization name)
  • کد سایت اول (Site code) و نام سایت اول (Site name)
  • رمز عبور و تکرار رمز عبور (به‌صورت مخفی و بدون نمایش کاراکتر)

پاک کردن متغیر محیطی پس از اتمام

Remove-Item Env:FORGEFLOW_BOOTSTRAP_SQLSERVER
✅
خروجی موفق: Result: Auth.Initialized; operation: ... — این دستور پس از تکمیل، راه‌اندازی مجدد روی همان دیتابیس را مسدود می‌کند.

مرحله ۶.۲ — بازیابی رمز عبور ادمین در مواقع اضطراری

در صورت فراموشی رمز ادمین، صفحه ورود قابلیت Forgot Password عمومی ندارد؛ اپراتور سرور باید با حضور مالک حساب از دستور reset-password استفاده کند:

$env:FORGEFLOW_RECOVERY_SQLSERVER = "Server=SQLHOST;Database=ForgeFlow;User Id=forgeflow_provision;Password=PROVISION_STRONG_PASS;Encrypt=True;" .\ForgeFlow.Bootstrap.exe reset-password # تایپ RECOVER → شناسه عددی کاربر (Verified account ID) → رمز جدید Remove-Item Env:FORGEFLOW_RECOVERY_SQLSERVER

پیکربندی IIS و HTTPS

تنظیم Application Pool

یک Application Pool با نام ForgeFlow بسازید:

  • .NET CLR Version: No Managed Code
  • Managed Pipeline Mode: Integrated
  • در Advanced Settings → Process Model: مقدار Load User Profile = True (برای نگهداری امن کلیدهای Data Protection)

فایل web.config

<?xml version="1.0" encoding="utf-8"?> <configuration> <location path="." inheritInChildApplications="false"> <system.webServer> <handlers> <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" /> </handlers> <aspNetCore processPath="dotnet" arguments=".\ForgeFlow.Web.dll" stdoutLogEnabled="false" hostingModel="InProcess"> <environmentVariables> <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" /> </environmentVariables> </aspNetCore> </system.webServer> </location> </configuration>

ساخت Website و اتصال HTTPS

سایت را به C:\inetpub\forgeflow متصل کنید، Binding از نوع https روی پورت 443 با گواهی SSL معتبر اضافه کنید و دسترسی خواندن/اجرا را به حساب App Pool بدهید:

icacls "C:\inetpub\forgeflow" /grant "IIS AppPool\ForgeFlow:(OI)(CI)RX"

چک‌لیست تعاملی Go-Live

۰ از ۱۲ مورد تکمیل شده
  • ASP.NET Core 10.0 Hosting Bundle (نسخه 10.0.14+) و ماژول WebSocket روی IIS نصب شده است.
  • فایل‌های ForgeFlow.Web در پوشه سایت و ForgeFlow.Bootstrap در مسیر مدیریتی مجزا کپی شده‌اند.
  • حساب SQL موقت/عملیاتی Provisioning از حساب محدود forgeflow_runtime جدا تعریف شده است.
  • Migration‌های هر ۳ کانتکست (AuthDbContext، OrganizationDbContext، DiagnosticsDbContext) اعمال شده‌اند.
  • ابزار ForgeFlow.Bootstrap initialize-deployment با موفقیت اجرا شده و حساب ادمین، سازمان و سایت اول ساخته شده‌اند.
  • متغیر محیطی FORGEFLOW_BOOTSTRAP_SQLSERVER پس از پایان راه‌اندازی پاک شده است.
  • تنظیمات ConnectionStrings__ForgeFlow و ASPNETCORE_ENVIRONMENT=Production با دسترسی محدود روی سرور ثبت شده‌اند.
  • در IIS App Pool گزینه No Managed Code و Load User Profile = True فعال است.
  • گواهی TLS/HTTPS معتبر روی پورت 443 تنظیم شده و کوکی امن فعال است.
  • درخواست GET /account/login کد وضعیت 200 برمی‌گرداند.
  • ورود با حساب ادمین و جابه‌جایی زبان فارسی/English و تم روشن/تیره بدون خطای کنسول کار می‌کند.
  • صفحه مدیریت ← لاگ خطاها خطای اتصال یا پیکربندی نشان نمی‌دهد.
۱۰

به‌روزرسانی نسخه جدید و روش بازگشت (Rollback)

روش استاندارد به‌روزرسانی

# ۱) پشتیبان‌گیری از پایگاه‌داده و فایل‌های وب فعلی Backup-SqlDatabase -ServerInstance SQLHOST -Database ForgeFlow -BackupFile "C:\backup\ForgeFlow_$(Get-Date -f yyyyMMdd_HHmm).bak" Stop-WebSite -Name "ForgeFlow" Copy-Item -Recurse "C:\inetpub\forgeflow" "C:\backup\forgeflow-prev" -Force # ۲) انتقال فایل‌های جدید و اعمال Migration‌های جدید ۳ کانتکست Copy-Item -Recurse ".\publish\web\*" "C:\inetpub\forgeflow\" -Force # اجرای dotnet ef database update برای AuthDbContext / OrganizationDbContext / DiagnosticsDbContext # ۳) راه‌اندازی مجدد Start-WebSite -Name "ForgeFlow"

بازگشت فوری در صورت خطا پس از به‌روزرسانی

Stop-WebSite -Name "ForgeFlow" Copy-Item -Recurse "C:\backup\forgeflow-prev\*" "C:\inetpub\forgeflow\" -Force # در صورت تغییر اسکیما، بازیابی بکاپ SQL یا بازگردانی Migration قبلی با تایید DBA Start-WebSite -Name "ForgeFlow"
